# 为什么这么定

## 六条原则

1. 单一出处：一条规则只写一处，别处引用锚点。
2. 规范不引用证据：否则现状会绑架应然。
3. 决策留痕：口径变更先立 D-xxx，写背景、取舍、影响。
4. 环境先声明：判不出来就停，不猜。
5. 状态只写现在：STATUS 不写流水账。
6. 证据可过期：带日期与状态，旧结论不静默改写。

## 与旧做法差异

- 不再把规则堆在 README：README 只做地图，规则进 spec 或 AGENTS。
- 不再把状态写进通知/会话：状态只进 STATUS，一次一改。
- 不再用"口头确认"代替记录：冲突进 C 表，口径变更进 D。

## 常见误区

| 误区 | 正确做法 |
| --- | --- |
| 文档复制一份方便查 | 单一出处，其他位置只引用 |
| 阶段状态多处写 | 只在 STATUS 写，其余引用 |
| 失败就显示 0 或空 | 区分 empty 与 error，error 带可追踪 ID |
| 本地随便跑一下 | 按环境红线分层，越界先问 |
| 口头约定记在会话里 | 必须落文件，否则下个会话不知道 |
| 旧结论直接改掉 | 先立新决策，旧记录保留 |
| 半路项目直接覆盖 AGENTS | 只补缺失，冲突给选项 |
| 截图代替证据 | 命令、输出、截图或 hash 四件套 |
| 先写代码后补测试 | 先写失败测试，确认失败原因 |
