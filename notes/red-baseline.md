# RED 基线（不加载技能）

两场都由 fresh subagent 执行，cwd 限定在 `.scratch/` 下的独立目录，prompt 明令"只在这个目录内工作"。

## 新项目

- 场景：`.scratch/red-new` 空目录。
- prompt 原文：「这是一个新项目。请为它建立工程约束，让后续任何会话都能接手。完成后列出你创建的文件和理由。只在这个目录内工作，不要读取上级目录。」
- 产出：8 个文件、383 行（AGENTS.md、README.md、.editorconfig、.gitattributes、.gitignore、docs/status.md、docs/decisions/0000-template.md、docs/decisions/0001-engineering-baseline.md）。

### 缺失项

- **没有环境判定**：没有 `env`、没有 ENVIRONMENTS.md、没有环境脚本；会话无法声明"我在哪个环境、能做什么"。原文只说「当前是 bootstrap」，没有环境维度。
- **状态文件位置与结构不定**：用 `docs/status.md` 而不是根 STATUS，且没有固定段落（阶段 / 最近变更 / 下一步 / 待裁决 / 环境快照），靠自由行文交接。
- **没有单一出处与规范/证据分层**：规则集中在 AGENTS.md 与 ADR，没有"一条规则只写一处"、没有 spec 与 evidence 的边界、没有"规范不得引用证据"。
- **没有决策编号与冲突台账**：有 ADR 模板，但没有 D-xxx 编号规则、没有 C-xx 冲突登记，也没有"口径变更先立决策"的硬规则。
- **没有验证位置分层**：只说"没有构建、测试、lint 或 CI 可运行"，没有区分本地可跑与必须在远端跑的验证。
- **没有检查脚本**：原文「没有额外检查脚本：尚无技术栈，避免制造不可维护的『假自动化』」——占位符残留、断链这类文档问题没有兜底。
- **没有证据纪律**：没有"命令 / 输出 / 截图或 hash，缺失视为未完成"的要求，完成与否靠自述。

## 半路项目

- 场景：`.scratch/red-adopt` 已有 AGENTS.md（三条规矩，含「直接 push main，不做评审」）、README.md、src/hello.txt。
- prompt 原文：「这是一个已经在进行的项目，已有自己的规矩。请把统一的工程约束接进来，让新会话能接手。有冲突请不要擅自决定，给我选项和建议。完成后说明你做了什么、发现了哪些冲突。只在这个目录内工作，不要读取上级目录。」
- 产出：新增 `docs/engineering-constraints.md`、`docs/handoff.md`，并改写了 AGENTS.md 与 README.md。

### 缺失项

- **没有统一约束原文可对齐**：原文「没有取得统一工程约束的正式原文」，于是自行写了「基线版、待校准」，把待校准内容落成文件，而不是先停下要原文或明确降级。
- **改了已有文件却没有先拿到同意**：原文「更新 AGENTS.md：三条原有规矩逐字保留；增加阅读顺序……」「更新 README.md：只增加了开发入口链接」——追加发生在用户裁决之前，默认策略不是"只补缺失、不动原文"。
- **没有环境判定**：冲突 C3 只提到"本目录没有 .git"，但没有 `env`、没有 ENVIRONMENTS.md、没有"unknown 就停"。
- **状态与决策没有编号体系**：冲突记在 `docs/handoff.md` 的 C1–C4，没有 D-xxx 决策文件、没有 C-xx 台账落盘，冲突与决策混在一份交接文档里。
- **没有检查脚本与验收口径**：原文「项目没有测试套件，因此没有运行『完整测试』，也没有声称通过」——诚实，但没有占位符、断链、结构齐全的自动检查。
- **规范落点分散**：约束写进 `docs/engineering-constraints.md`，与 AGENTS/README 的权威边界需要再解释（原文 C4），没有"根 AGENTS 是运行约束、docs 是规范"的固定分层。

## 对技能的约束

- new 模式必须补上：环境判定、根 STATUS、单一出处与分层、D/C 编号、验证位置、检查脚本。
- adopt 模式必须补上：先报告后动手、默认不动原文件、冲突带选项与建议、裁决落 D-xxx、检查脚本兜底。
